运行机制

服务按每个群组配置的 cron 时间往群里发签到指令。可以接多个 Telegram 账号和多个机器人，每个群组单独指定「用哪个账号 / 哪个机器人」签到，没指定就跟随「系统设置 → 谁来签到」的默认值。定时点没在线（容器休眠或重启）时，补签线程会在上线后立刻补一次，保证每天至少成功一次。

两种方式任选其一。扫码更省事：点「扫码登录」后出现二维码，用手机 Telegram（设置 → 设备 → 连接设备）扫一下即可，不需要等短信。验证码方式则会在 Telegram 官方对话里收到一串码。若账号开启了两步验证，两者都会再要求输入验证密码。登录会话分别保存在各自的账号记录里，互不影响，重启容器也不会丢失。

GitHub 上的备份是脱敏的

上传前会自动抹掉面板密码、各种 Token、api_hash、session_string、手机号和 Business 授权，聊天记录也不传。所以这里只能存「结构快照」，不能拿它完整恢复登录态——真要迁移或恢复，用 WebDAV 或本地下载的那份。想完全不上传，把下面的「自动同步」设成关闭即可。

没有 Token？ 点这里一键生成 —— 名称、有效期（90 天）和权限（Contents: Read and write）都已在链接里预填，打开后只需在「Repository access」选 Only select repositories 勾上备份仓库，再点 Generate token 复制回来。

提示：GitHub 对「仓库不存在」和「Token 没权限」都回同一句 404。点「测试连接」时，程序会用你的 Token 反查它实际能访问哪些仓库，直接告诉你仓库名该怎么写、或者是不是 Repository access 没勾上。

AI 智能体

每个智能体可以有自己的名字、模型、接口和提示词，互不影响。机器人默认用带「默认」标签的那个，也可以单独指定。支持任何兼容 OpenAI /chat/completions 协议的服务：DeepSeek、硅基流动、Kimi、通义、one-api 中转等，base_url 填到 /v1 为止。

模型

填好接口地址和 Key 会自动去读这家接口的模型列表；想在同一家接口上用多个模型，勾选多个就行，保存时会一个模型建一个智能体。

接口只对大陆网络开放、而主机部署在境外时，直连会报「Connection reset by peer」。这种情况需要填一个境外可用的代理，或改用全球可达的接口。
