运行机制

服务按每个群组配置的 cron 时间往群里发签到指令。可以接多个 Telegram 账号和多个机器人，每个群组单独指定「用哪个账号 / 哪个机器人」签到，没指定就跟随「系统设置 → 谁来签到」的默认值。定时点没在线（容器休眠或重启）时，补签线程会在上线后立刻补一次，保证每天至少成功一次。

API 凭据怎么来

打开 my.telegram.org/apps 登录后创建应用，复制 api_id 和 api_hash。每个账号可以用同一套凭据，但建议各用一套，避免同 IP 多账号同时登录被风控。

登录说明

两种方式任选其一。扫码更省事：点「扫码登录」后出现二维码，用手机 Telegram（设置 → 设备 → 连接设备）扫一下即可，不需要等短信。验证码方式则会在 Telegram 官方对话里收到一串码。若账号开启了两步验证，两者都会再要求输入验证密码。登录会话分别保存在各自的账号记录里，互不影响，重启容器也不会丢失。

提示

cron 为 5 段格式：分 时 日 月 周。随机延迟会在每次发送前增加 0 到设定值之间的等待，降低固定时间点的机械特征。模拟运行适合先验证连接和群组是否正确。

添加机器人
  1. 在 Telegram 搜索 @BotFather，发送 /newbot
  2. 按提示起名字和用户名（用户名必须以 bot 结尾）
  3. 把 BotFather 返回的 token 粘到下面，点「校验并添加」
  4. 私聊里先给机器人发一句话，或在群里把它拉进去并给「读取消息」权限

AI 模型设置

支持任何兼容 OpenAI /chat/completions 协议的服务：DeepSeek、硅基流动、Kimi、通义、one-api 中转等。base_url 填到 /v1 为止。

接口只对大陆网络开放、而主机部署在境外时，直连会报「Connection reset by peer」。这种情况需要填一个境外可用的代理，或改用全球可达的接口。
